1. Strategic Vision & Executive Summary

Strategic Core

Scholar SMS represents an enterprise-grade, integrated institutional solution engineered to eliminate administrative fragmentation in modern primary, secondary, and tertiary educational organizations. Traditionally, institutions grapple with disparate software packages for student registration, staff payroll, daily roll call, online examinations, report card generation, and guardian communication. Scholar SMS consolidates these disparate functions into a unified, secure, high-performance ecosystem.

3. Modern LMS Tests, Quizzes & Examinations Suite

Pedagogical Technology

The LMS suite incorporates a comprehensive Computer-Based Testing (CBT) engine designed to support high-stakes formal examinations (Midterms, Final Semesters) as well as continuous formative assessments (Weekly Quizzes, Practice Drills).

Studio Q&A Authoring Studio

An intuitive workspace enabling faculty to author questions across 5 distinct formats:

  • Single-Choice MCQ: Standard choice with exactly one validated correct option.
  • Multi-Select MCQ: Multi-answer selection requiring all correct choices for credit.
  • True / False: Dedicated tactile truth-value validation.
  • Short Answer: Pattern and comma-separated keyword matching engine.
  • Long Essay: Subjective analytical submissions reserved for instructor rubric review.

CBT Student Examination Terminal

A distraction-free exam player built for strict focus and reliability:

  • Synchronized Countdown: Real-time timer with server-backed duration checks.
  • Question Palette: Visual matrix showing answered, current, and unanswered items.
  • Asynchronous Auto-Save: Background auto-saving prevents data loss on network drops.
  • Anti-Cheating Safeguards: Question order randomization and choice shuffling.
  • Zero-Timer Enforcement: Automatic answer freeze and submission when time expires.

Grading Rubric Review & Submissions Console

Centralized evaluation interface displaying candidate attempt rosters, submission timestamps, and automated scores. Provides dedicated mark-allocation inputs and qualitative feedback fields for subjective essay prompts.

Report Candidate Performance Report Card

Post-submission diagnostic report providing total marks, percentage, pass/fail status, duration taken, attempt counting, and solution explanations (when permitted by instructor policy).

4. Dual-Grading Scheme & Holiday Calendar Safeguards

Academic Architecture

To bridge digital learning with traditional physical classroom activities, Scholar SMS pioneers an integrated Dual-Grading Matrix paired with an intelligent Academic Calendar Engine.

Dual-Grading Framework (Continuous LMS + Classroom Offline)

Recognizing that education occurs both in digital labs and physical lecture halls, the platform allows academic administrators to configure custom evaluation weighting per course:

Grading Component Standard Allocation Data Source & Evaluation Channel
Online Digital LMS 30% – 50% Interactive CBT Quizzes, Module Knowledge Checks, Automated Objective Grading.
Offline Classroom Coursework 50% – 70% Physical Midterms, Laboratory Practicals, Written Final Papers, Oral Presentations.
Terminal Synthesis 100% Automated weighted composite calculated dynamically on Official Terminal Report Cards.

Intelligent Calendar & Attendance Safeguards

The academic calendar module registers National Holidays, Regional Holidays, and Institutional Non-Instructional Days. The daily attendance roll call engine cross-references this calendar automatically—ensuring that students are never recorded as absent during school breaks and overall institutional attendance percentages remain accurate.

Cryptographically Chained (SHA-256) Audit Trail

Scholar SMS guarantees institutional transparency through a tamper-evident cryptographic ledger modeled on Merkle chaining principles. Every significant administrative action—including student enrollment, grade modification, attendance sealing, and broadcast dispatch—is cryptographically hashed with the preceding block's hash:

Current_Hash = SHA-256(Previous_Hash + Actor_ID + Action_Type + Entity_Payload + Timestamp)

An interactive Audit Verification Console allows administrators and external auditors to recalculate the chain from the Genesis block to the tip in real time, detecting unauthorized database mutations instantly.
